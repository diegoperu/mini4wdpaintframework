# UAT-001 — Primo Test con Operatore Esterno

**Mini4WD Manual SDK** · User Acceptance Test
**Data:** 2026-07-01/02 · **SDK testato:** v2.4.0 · **Correzioni rilasciate in:** v2.4.1
**Progetto di test:** `Dash-01_Shadow_Emperor` (sic — vedi Errore 4)

---

## Contesto

Primo utilizzo del framework da parte di un operatore che NON ha partecipato allo
sviluppo, seguendo esclusivamente la documentazione del repository.

**Percorso eseguito dall'operatore:**

1. Clone del repository GitHub
2. Lettura di `PROJECT_BOOTSTRAP.md` e `AI_BOOTSTRAP_PROMPT.md`
3. Creazione `Projects/Dash-01_Shadow_Emperor/`
4. Creazione cartelle `Images/`, `Output/`, `Notes/`
5. Compilazione `PROJECT.yaml`
6. Inserimento immagini in `Projects/.../Images/`
7. Bootstrap → **OK**
8. Tentativo di generazione P001
9. Validation → **FAIL**

L'operatore non ha modificato altri file.

**Esito:** Bootstrap corretto; workflow ambiguo con errori di utilizzo indotti dalla
documentazione. **Conclusione: il problema non è l'utente — è la documentazione.**

---

## Errori riscontrati

### Errore 1 — Validation FAIL su template non generato

- **Descrizione:** la validazione di P001 è fallita subito dopo il bootstrap: campi
  vuoti, placeholder non risolti, contenuto "mancante".
- **Causa:** i moduli `ApprovedAssets/Text/P00x/` sono spediti come **template** in
  `status: draft` con campi vuoti. Nessun documento distingueva Template / Draft /
  Approved: il validatore (e l'operatore) hanno trattato il template come contenuto
  finale. Inoltre l'ordine "prima genera, poi valida" non era esplicito nel percorso
  operatore.
- **Correzione applicata:** introdotta la sezione **§Validation Scope** nelle due
  suite QA: i template non si validano mai; il QA si applica solo a contenuto
  generato; regole per riconoscere un template.
- **Documenti aggiornati:** `Tests/ContentValidation.md`, `Tests/TextValidation.md`,
  `LIFECYCLE.md` (nuovo), `OperatorGuide/06_Errori_Comuni.md §E01`,
  `Docs/AI_BOOTSTRAP_PROMPT.md` (prompt Fase 3 dichiara l'ambito).

### Errore 2 — Falsi positivi linguistici su termini tecnici e nomi commerciali

- **Descrizione:** segnalati come violazioni "inglese vietato": Primer, Topcoat,
  Masking Tape, Chrome Silver, Gun Metal, Semi Gloss Black, Flat Black, TS-37, XF-1,
  X-10, X-11, Header, Footer, "draft".
- **Causa:** `Config/LANGUAGE_POLICY.yaml` non distingueva tra contenuto editoriale
  (italiano obbligatorio) e metadati/termini tecnici/nomi commerciali/chiavi YAML
  (language-neutral). La whitelist copriva solo 4 termini.
- **Correzione applicata:** §exceptions riorganizzata in 5 categorie esplicite
  (paint codes, technical terms, commercial names, YAML/schema, structural metadata)
  con whitelist estesa; aggiunta §validation_scope; aggiornato TX-001-K.
- **Documenti aggiornati:** `Config/LANGUAGE_POLICY.yaml`, `Tests/TextValidation.md`,
  `OperatorGuide/06_Errori_Comuni.md §E02`, `OperatorGuide/07_FAQ.md`.

### Errore 3 — Ambiguità sulla posizione delle immagini di riferimento

- **Descrizione:** documenti in conflitto: `PROJECT_BOOTSTRAP.md` e
  `Docs/LOAD_ORDER.md` indicavano `Projects/{Modello}/Images/`; `Core/WORKFLOW.md §0.4`
  e `Build/Pipeline.md §Phase 1` indicavano `Assets/ReferenceModels/{Modello}/`.
- **Causa:** doppia convenzione ereditata da versioni precedenti, mai unificata.
- **Correzione applicata:** **convenzione unica v2.4.1** — l'operatore usa sempre e
  solo `Projects/{Modello}/Images/`; `Assets/ReferenceModels/` è riservata al
  Maintainer per i progetti di riferimento SDK.
- **Documenti aggiornati:** `PROJECT_STRUCTURE.md` (nuovo),
  `Projects/PROJECT_BOOTSTRAP.md` (riscritto), `Projects/README.md`,
  `Assets/ReferenceModels/README.md`, `OperatorGuide/06_Errori_Comuni.md §E03`.

### Errore 4 — Nome cartella progetto con trattino

- **Descrizione:** l'operatore ha creato `Projects/Dash-01_Shadow_Emperor/` (trattino
  dopo "Dash").
- **Causa:** la regola "spazi → underscore" era documentata, ma il divieto di
  trattini nel nome cartella non era esplicito; la coesistenza con `modelSlug` in
  kebab-case (dove i trattini sono OBBLIGATORI) creava confusione.
- **Correzione applicata:** regola esplicita con esempi giusti/sbagliati: cartella =
  underscore, slug = trattini.
- **Documenti aggiornati:** `PROJECT_STRUCTURE.md`, `Projects/PROJECT_BOOTSTRAP.md`,
  `FIRST_PROJECT.md`, `OperatorGuide/06_Errori_Comuni.md §E04`.

### Errore 5 — Set di file progetto ambiguo

- **Descrizione:** `Projects/README.md` richiedeva 6 file (PROJECT.yaml, PROJECT.md,
  CHECKLIST.md, COLOR_SCHEME.yaml, PDF_CONFIG.yaml, README.md); `PROJECT_BOOTSTRAP.md`
  ne indicava 1. L'operatore ne ha creato 1 — bootstrap comunque OK.
- **Causa:** nessun documento definiva il set MINIMO vs il set COMPLETO.
- **Correzione applicata:** set minimo ufficiale = `PROJECT.yaml` + `Images/` +
  `Output/` + `Notes/`; gli altri template dichiarati opzionali.
- **Documenti aggiornati:** `PROJECT_STRUCTURE.md`, `Projects/README.md`,
  `Projects/PROJECT_BOOTSTRAP.md`, `OperatorGuide/06_Errori_Comuni.md §E05`.

### Errore 6 — Convenzione placeholder doppia

- **Descrizione:** `AI_ENTRYPOINT.md` impone `TODO:` come unico placeholder;
  `Config/LANGUAGE_POLICY.yaml §approved_placeholders` elenca `[TITOLO]`,
  `[SOTTOTITOLO]`, ecc.
- **Causa:** due famiglie di placeholder con ruoli diversi mai spiegati insieme:
  `TODO:` = dato mancante (operatore/AI); `[TITOLO]`-style = marcatori interni dei
  template SDK.
- **Correzione applicata:** regola chiarita nella documentazione operatore: si usa
  solo `TODO:`; un `[TITOLO]` residuo in contenuto generato = generazione incompleta.
- **Documenti aggiornati:** `OperatorGuide/06_Errori_Comuni.md §E06`,
  `OperatorGuide/07_FAQ.md`, `Tests/TextValidation.md §Validation Scope`.

### Errore 7 — Fasi, prompt e cambio chat non mappati

- **Descrizione:** l'operatore non sapeva con certezza quale prompt usare in quale
  momento né quando aprire una nuova chat; i prompt A–F erano elencati per tipo, non
  per fase.
- **Causa:** mancava una mappa fase → prompt → chat.
- **Correzione applicata:** `Docs/AI_BOOTSTRAP_PROMPT.md` riorganizzato per fasi
  (Bootstrap → Testi → QA → Rendering → PDF), ognuna con Input / Output / Prompt /
  Nuova chat SÌ-NO; creata la state machine `WORKFLOW.md`.
- **Documenti aggiornati:** `Docs/AI_BOOTSTRAP_PROMPT.md` (riscritto), `WORKFLOW.md`
  (nuovo), `OperatorGuide/02_Workflow.md` (nuovo), `START_HERE.md` (nuovo).

### Errore 8 — Nessun punto di ingresso per l'operatore umano

- **Descrizione:** il repository aveva entry point per l'AI (`AI_ENTRYPOINT.md`,
  `BOOTSTRAP.md`) ma nessun "leggimi per primo" per l'operatore; README lungo e
  architetturale.
- **Causa:** documentazione scritta dal punto di vista del framework, non dell'utente.
- **Correzione applicata:** creato il layer operatore: `START_HERE.md` +
  `OperatorGuide/` (7 documenti) + tutorial `FIRST_PROJECT/RENDER/PDF.md` +
  `FILE_MATRIX.md`, `WHO_MODIFIES_WHAT.md`, `OPERATOR_PROFILE.md`, `LIFECYCLE.md`,
  `PROJECT_STRUCTURE.md`.
- **Documenti aggiornati:** nuovi file sopra + `README.md` (sezione di ingresso).
