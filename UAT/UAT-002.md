# UAT-002 — Test Runtime Gemini: Fase 3/4 (Render Engine)

**Mini4WD Manual SDK** · User Acceptance Test
**Data:** 2026-07-03 · **SDK testato:** v2.4.1 / v2.5.0 · **Runtime:** Google Gemini (Nano Banana 2)
**Progetto di test:** `Magnum_Saber_Premium / Cotton_Candy_Drift` · **Fase testata:** 3/4 — Render Engine

---

## Contesto

Test di compatibilità del runtime Gemini (modello Nano Banana 2) nella Fase 3/4 del
framework (generazione immagine illustrata da `content.yaml` locked + QA visivo del render).
Il progetto `Magnum_Saber_Premium / Cotton_Candy_Drift` aveva già completato con successo
la Fase 2/3 (generazione testi + QA) su ChatGPT Web.

Gemini era elencato come runtime "pianificato" in `Docs/RUNTIMES.md` e come compatibile
nella tabella di `Docs/AI_BOOTSTRAP_PROMPT.md §Compatibilità`. Questo UAT costituisce
la verifica concreta di quella compatibilità dichiarata.

**Percorso eseguito:**

1. Fase 2/3 già completata su ChatGPT Web (content.yaml P001–P010 generati e QA superato)
2. **Tentativo 1:** Fase 4 su Gemini con ZIP completo del repository (266 file)
3. **Tentativo 2:** Fase 4 su Gemini con ZIP ridotto (15 file — solo documenti strettamente necessari al render P001)
4. **Tentativo 3:** Fase 4 con prompt ulteriormente rinforzato (hex bloccati, whitelist testo chiusa, divieto esplicito di priors, divieto leak metadati)

**Esito pre-analisi:** tutti e tre i tentativi hanno prodotto output non conformi al
framework. La conclusione non è "prompt da migliorare" ma "runtime strutturalmente
inaffidabile per la Fase 3/4".

---

## Errori riscontrati

### Errore 1 — ZIP completo rifiutato; output allucinato prodotto prima del rifiuto

- **Descrizione:** Gemini ha rifiutato il repository completo (266 file) con errore
  esplicito "troppi file da elaborare". Tuttavia, **prima** di emettere il messaggio di
  errore, con lo stesso ZIP caricato, aveva già prodotto un output testuale completo di
  Fase 4: nessuna immagine generata, checklist QA con tutti `[PASS]` fittizi, schema
  colore inventato, testo con kanji giapponese, decalcomanie inesistenti non presenti nel
  progetto.
- **Causa:** Gemini ha generato la risposta completa a partire dai propri priors sul brand
  Tamiya, **senza attendere la lettura dei file**, e solo successivamente ha rilevato il
  limite di elaborazione. Il comportamento inverte l'ordine corretto: leggi → genera. In
  questo caso: genera prima → fallisci poi.
- **Regole violate:** RULE-060 (testo esclusivamente da `content.yaml`), RULE-004 (zero
  kanji/hiragana/katakana).
- **Evidenza:** output conteneva schema colore non corrispondente a Cotton Candy Drift,
  kanji nella sezione titolo, checklist QA con esiti falsificati (`[PASS]` su contenuto
  mai valutato), decalcomanie non presenti nel `PROJECT.yaml`.
- **Correzione applicata:** nessuna — il problema è nel comportamento del runtime, non nel
  framework. **Remediation:** aggiornato flag di compatibilità in `SDK_CONTEXT.yaml`.

### Errore 2 — ZIP ridotto: `content.yaml` ignorato, metadati interni leaked nel render

- **Descrizione:** con ZIP ridotto (15 file — solo i documenti necessari al render P001),
  il limite file è stato aggirato. Il render prodotto ha ignorato `content.yaml`:
  - Schema colore: livery di scatola Tamiya originale (bianco/blu/rosso) invece di
    Cotton Candy Drift (azzurro/rosa/nero) — Gemini ha usato la propria conoscenza del
    prodotto reale invece di leggere i dati del progetto
  - Decalcomanie inventate e kanji
  - Testo prevalentemente in inglese
  - **Più grave:** citazioni interne del framework stampate come testo visibile
    nell'immagine finale: `[cite: Core/COMPONENT_SYSTEM.md: ...]`, testo letterale
    `"Status: LOCKED (yaml Approved)"` incluso nel render come elemento grafico
- **Causa:** (a) Gemini non isola il contesto fornito dai propri priors di training —
  quando esistono conoscenze pregresse sul soggetto, le usa in sostituzione del contenuto
  strutturato fornito; (b) il meccanismo di citazione delle fonti di Gemini espande il
  contesto interno alle fonti citate e inietta referenze SDK come testo nel contenuto
  visibile.
- **Regole violate:** RULE-044 (nessun metadato interno visibile nel render), RULE-060,
  RULE-004, RULE-001 (lingua italiana obbligatoria), RULE-003 (non inventare dati).
- **Evidenza:** immagine renderizzata mostrava livery "Magnum Saber" da packaging Tamiya
  (non Cotton Candy Drift); testo `[cite: Core/COMPONENT_SYSTEM.md: ...]` visibile come
  elemento della pagina illustrata.
- **Correzione applicata:** nessuna — problema strutturale del runtime. **Remediation:**
  aggiornato flag di compatibilità.

### Errore 3 — Prompt rinforzato: risposta completamente scollegata dall'input

- **Descrizione:** con prompt ulteriormente rinforzato (valori hex bloccati, whitelist
  testo chiusa sui soli valori presenti in `content.yaml`, divieto esplicito di usare
  priors sul prodotto Tamiya reale, divieto esplicito di leak metadati SDK), Gemini ha
  risposto con testo completamente non correlato al task: un confronto tra Cotoletta alla
  Milanese e Wiener Schnitzel. Nessuna relazione con il prompt, nessuna immagine generata,
  nessun tentativo di elaborazione del contesto fornito.
- **Causa:** malfunzionamento del turno di generazione — non riconducibile a qualità o
  struttura del prompt. Il modello ha ignorato l'intero contesto e ha prodotto output da
  un dominio completamente diverso. Questo comportamento è indicativo di instabilità
  strutturale del runtime con input strutturati complessi (molti vincoli, molte istruzioni
  negative, contesto lungo).
- **Evidenza:** risposta letterale sul tema gastronomico italo-austriaco. Zero contenuto
  correlato al framework o al progetto Mini4WD.
- **Correzione applicata:** nessuna — non è un problema correggibile tramite prompt
  engineering. **Remediation:** runtime rimosso dalla lista dei runtime supportati.

## Esito

| Voce | Valore |
|---|---|
| Runtime testato | Google Gemini (Nano Banana 2) |
| Fase testata | Fase 3/4 — Render Engine |
| Progetto | Magnum_Saber_Premium / Cotton_Candy_Drift |
| Tentativo 1 — ZIP completo | **FAIL** — limite file + output allucinato pre-errore |
| Tentativo 2 — ZIP ridotto | **FAIL** — `content.yaml` ignorato, metadati leaked nel render |
| Tentativo 3 — Prompt rinforzato | **FAIL** — risposta scollegata dall'input (gastronomica) |
| Regole violate | RULE-001, RULE-003, RULE-004, RULE-044, RULE-060 |
| Correzioni al framework | Nessuna |
| Correzioni alla documentazione | `SDK_CONTEXT.yaml`, `Docs/RUNTIMES.md`, `Docs/AI_BOOTSTRAP_PROMPT.md`, `BOOTSTRAP.md`, `README.md`, `PromptEngine/README.md`, `Documentation/QualityManagement/07_KNOWN_ISSUES.md` |
| Compatibilità Gemini | **Revocata** — non supportato |

**Decisione:** Gemini degradato da `compatibile (pianificato)` a `non supportato` in tutti
i documenti del framework. Il problema non è correggibile tramite prompt engineering: è una
limitazione strutturale del runtime nella gestione di contenuto strutturato con isolamento
del contesto dai priors di training.

**Runtime raccomandato per Fase 3/4:** ChatGPT Web (GPT-4o + DALL-E).

**Follow-up consigliato (UAT-003):** verificare ChatGPT Web su Fase 3/4 completa
(P001–P010 rendering) partendo dai `content.yaml` locked del progetto Magnum_Saber.
